# 탐험 보상용 장식과 배치 연결

## 구현 상태

장식 4종의 프리팹과 접촉 반응, 보유권 지급 함수, 기존 배치·이동·회수·저장·복원 경로를
연결했다. 탐험 자체와 포인트·뽑기권을 포함한 귀환 보상 정산은 아직 구현하지 않았다.

| 저장 번호 | 프리팹 | 구성 | 슬라임 이동 |
| --- | --- | --- | --- |
| 0 | 기존 범퍼 | 기존 기능 유지 | 접촉 시 밀어냄 |
| 1 | 기존 대포 | 기존 기능 유지 | 접촉 시 발사 |
| 2 | `Decor_FlowerPatch` | 꽃·풀 이미지 6장을 조합한 꽃밭 | 통과, 충돌체 없음 |
| 3 | `Decor_FlowerCushion` | 꽃 모양 방석 | 통과, 충돌체 없음 |
| 4 | `Decor_FlowerBasket` | 꽃바구니와 분리된 그림자 | 통과, 충돌체 없음 |
| 5 | `Decor_FireflyLantern` | 랜턴·그림자·빛·반딧불 5개 | 통과, 감지 트리거만 사용 |

프리팹은 `Assets/03.Prefabs/Decorations/`에 있다. 기존 `PlayGround` 정렬 레이어를
사용하므로 슬라임 뒤에 그려진다. 위치에 따라 앞뒤를 바꾸는 정렬은 포함하지 않는다.

랜턴은 장식장의 착지한 슬라임이 감지 영역에 들어오면 약 2.4초 동안 반응하고,
종료 후 1.5초 동안 다시 반응하지 않는다. 슬라임을 밀거나 잡지 않고, 끌고 있는
슬라임에는 반응하지 않는다. 배치 모드에서는 `PlaygroundObjectField`가 감지와 연출을
멈춘다. 장식장을 벗어나 비활성화될 때도 빛·반딧불을 초기화한다.

이미지 원본은 유지했다. Unity Sprite Editor 데이터 제공자로 주 스프라이트 ID를
유지하면서 투명 여백과 자동 분할 잡음 조각을 정리했다.

## 배치와 지급

- 배치 모드 아래쪽에 기존 하단 메뉴와 같은 가로 스크롤 선택 패널을 표시한다. 범퍼·대포와 장식 4종은 아이콘과 이름이 있는 한 줄 카드로 고르고, 치우기·완료는 패널 위에 고정한다.
- 미보유 또는 이미 배치한 종류는 선택할 수 없다. 기존 종류당 1개 제한을 유지한다.
- 상점에는 새 상품을 추가하지 않으며, 신규·기존 계정에 자동 지급하지 않는다.
- `SlimeManager.TryGrantDecoration(type)`이 장식 소유권을 추가하고 저장·변경 이벤트를
  발생시킨다. 초기화 전, 저장 읽기 실패 상태, 장식 외 종류, 중복 소유는 `false`다.
- 이 함수는 장식 소유권만 처리한다. 탐험 완료 여부와 중복 정산 방지, 포인트·뽑기권
  지급까지 포함한 귀환 보상 처리는 후속 구현이다.

하단 선택 패널은 기존 메뉴의 `HorizontalButtonScroll`과 `RectMask2D`를 재사용한다.
화면 너비는 `PortraitColumnPanelWidth`로 맞추며, 배치 모드의 입력 차단 영역은
선택 패널과 고정 동작 버튼을 계속 참조한다.

## 저장 호환 계획과 적용

`SlimeStatus` 스키마를 16에서 17로 올린다. 필드·키·클라우드 컬렉션·계정 소유자는
변경하지 않는다. `OwnedPlaygroundObjects`와 `PlacedObjects`를 그대로 사용한다.

1. 기존 범퍼 0·대포 1을 유지하고 새 종류는 2~5에 추가한다.
2. v16 이하 문서는 기존 `UpgradeInstanceData` 경로로 v17로 승격한다.
3. 짧은 보유 배열은 기존 `SlimeStatus.RestorePlayground`가 읽고, 없는 새 종류는 0으로
   남긴다. 기존 소유권·배치 위치는 유지하며 다음 저장은 6칸의 보유 배열을 쓴다.
4. v17 문서를 v16 앱으로 읽으면 기존 미래 버전 거부 경로가 진입을 차단한다.
   구버전이 모르는 장식을 잘라내 저장하는 것을 막으므로, v17로 저장한 계정의 앱을
   v16 이하로 되돌려 계속 플레이하는 흐름은 지원하지 않는다.

## 사용자 확인 절차

개발 중에는 탐험 없이도 Editor 로컬 계정에서 확인할 수 있게 지급 메뉴를 제공한다.
이 메뉴는 `Editor` 폴더에 있으므로 Android 빌드에는 포함되지 않는다. 실행하면
Editor의 `LocalPlayer` 저장에 소유권이 남는다. 에이전트는 메뉴를 실행하지 않았다.

1. LoginScene에서 사용자가 직접 Play Mode를 시작하고 장식장에 들어간다.
2. `Tools > Decorations > Grant Test Decorations (Editor Local Save)`를 누른다.
   초기화가 끝나기 전에는 메뉴가 비활성화된다. 정상이라면 미보유 장식이 지급되고,
   메뉴를 다시 눌러도 이미 보유한 장식은 늘지 않는다.
3. 장식장 하단의 기존 배치 진입 버튼으로 배치 모드를 연다. 범퍼·대포·꽃밭·꽃 방석·
   꽃바구니·반딧불 랜턴의 6개 카드를 좌우로 끌어 모두 볼 수 있어야 한다.
   보유한 새 장식은 선택 가능하고 미보유 범퍼·대포는 선택 불가능해야 한다. 드래그가 카드 클릭이나 방 안 배치로 이어지지 않아야 하며, 치우기·완료는 스크롤과 무관하게 고정되어야 한다.
4. 장식을 하나씩 방 안의 서로 떨어진 위치에 놓는다. 배치 후 해당 버튼은 비활성화되고,
   장식을 끌어 옮기거나 치우면 기존과 같은 규칙으로 처리되어야 한다.
5. 배치를 완료한 뒤 슬라임이 정적 장식 위로 멈춤·튕김 없이 통과하는지 확인한다.
   장식과 겹친 슬라임을 눌러도 구경하기가 열려야 한다.
6. 랜턴 감지 영역으로 슬라임이 자연스럽게 들어오면 빛과 반딧불이 나타났다 사라져야
   한다. 배치 모드에 다시 들어가면 반응이 멈추고, 공간 전환 후 연출이 남지 않아야 한다.
7. 플레이를 종료하고 LoginScene에서 다시 시작한다. 소유권과 배치 위치가 복원되어야
   한다. 치운 장식은 미배치 상태로 남고 다시 배치할 수 있어야 한다.
8. 기존 v16 로컬 저장의 복사본으로도 진입한다. 범퍼·대포 보유권과 위치가 유지되고,
   새 장식은 지급 메뉴 실행 전까지 미보유여야 한다. 실제 플레이어 문서는 지우지 않는다.

Play Mode, 실제 저장·재접속, Android 기기, 클라우드 복원은 사용자 검증으로 남긴다.
