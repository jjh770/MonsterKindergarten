## 2. 방법과 한계

- **AI 점검**: `unity-editor-mcp`로 에디터에 붙어 Play Mode를 직접 진행했다. 각 단계마다 화면을 캡처하고, 튜토리얼 대사·안내 문구·토스트를 읽어 판단했다.
- **입력 재현**: `Assets/02.Scripts/Editor/QA/QaDriver.cs`가 화면 좌표를 누른다.
  - UI는 실제 터치처럼 `EventSystem` 레이캐스트의 맨 위 대상을 누른다. 덮인 버튼이나 튜토리얼 구멍 밖은 실제 기기처럼 막힌다.
  - 슬라임은 `Clicker`의 누름·끌기·뗌 경로를 그대로 탄다.
- **새 계정**: 에디터 PlayerPrefs를 모두 지우고 동의 화면부터 시작했다. 진행에 필요한 등급·티켓·포인트는 매니저 API로 넣었다(정상 범위 값만 썼다).
- **문구 줄 수**: 실행 중인 대화창(폭 806)에 모든 대사를 넣어 TMP가 실제로 몇 줄로 나누는지 쟀다. 한 줄에 한글 약 20자가 들어간다.
- **한계**: 아래 항목은 에디터에서 확인할 수 없어 기기 확인이 필요하다.
  - Google Play 로그인, Firebase 클라우드 저장, 실제 광고
  - 손가락 터치 판정(끌기 문턱, 터치 범위)
  - 소리의 실제 크기와 어울림
  - 기기 성능, 노치
  - 화면 캡처는 1080×2340 기준 한 해상도만 확인했다.

## 5. 동작은 있는데 소리가 없는 사건 (수정하지 않음)

새 소리를 고르는 일은 기획 판단이라 목록만 남긴다.

| 사건 | 현재 | 제안 |
|---|---|---|
| 탐험 출발 / 귀환 보상 수령 | 무음 (버튼 클릭음만) | 출발: `AreaTransition` 재사용, 수령: `OfflineRewardCollect` 재사용 |
| 도감 등록, 도감 효과 상승 토스트 | 무음 | `FeatureUnlock` 재사용 |
| 놀이기구 놓기 / 치우기 | 무음 | `SlimeLand`/`UIClick` |
| 상점 구매 실패(포인트 부족) | 토스트만 | 업그레이드처럼 `InsufficientCurrency` |
| 필드에 뽑기권이 떨어질 때 | 무음 | 작은 효과음 (드롭 빈도가 낮으면 유효) |
| 자동 합성 쿨다운 완료 | 무음(링 깜빡임만) | 선택 |
| 엔딩 BGM | 장식장 BGM이 그대로 이어짐 | 전용 곡 검토 |

## 6. 발견했지만 고치지 않은 사항

판단이 필요하거나 레이아웃·기능 변경이 필요한 것들이다. 우선순위는 제안이다.

| # | 우선 | 내용 | 근거 / 제안 |
|---|---|---|---|
| 1 | 높음 | **뽑기 확률표에 특별 슬라임 확률(3%, 피버 최대 10%)이 없다.** 표는 일반 결과만 합 100%로 보여 준다 | 실제 뽑기는 특별 판정을 먼저 한다(`GachaService.TryPick`). 표 위에 "특별한 슬라임 3%(실패할 때마다 +0.5%p, 최대 10%)" 한 줄을 넣는 것을 권한다. 유료 재화가 아니어도 확률 공개 관행에 맞추는 편이 안전하다 |
| 2 | 중간 | 상위 등급 튜토리얼 마지막 대화가 **비추는 업그레이드 카드를 가린다** | `NearSpotlight`로 지정돼 있다. 그런데 직전에 `TryShowSystemUpgradePanel()`이 패널을 밀어 올리는 중이라, 위치를 계산할 때 구멍이 아직 화면 아래에 있었던 것으로 보인다(추정). 패널 애니메이션이 끝난 뒤 대화를 띄우거나 위치를 다시 계산해야 한다 |
| 3 | 중간 | 뽑기 기계 상단 안내(흰 글자, 외곽선 없음)가 HUD의 포인트·타이머·광고 배지 위에 겹쳐 읽기 어렵다 | 안내 위치를 기계 아래로 옮기거나, 반투명 띠 또는 외곽선을 넣는다 |
| 4 | 중간 | 도감 효과 토스트와 튜토리얼 대화가 같은 순간에 뜨면 토스트가 대화에 가려진다(12종·15종 등록 직후) | 튜토리얼이 도는 동안은 토스트를 미루거나 위치를 위로 올린다 |
| 5 | 중간 | 장식장 정보 튜토리얼 말풍선이 정보창의 이름·번호를 가린다("이름과 번호를 확인" 안내와 모순) | 그 단계에서는 말풍선을 패널 위나 아래로 옮긴다 |
| 6 | 중간 | **탐험 기능에 튜토리얼이 없고**, 도감 효과 창에도 탐험 해금(13종)이 없다 | 장식장 메뉴에서만 보이는 버튼이라 발견하기 어렵다. 처음 열 때 짧은 안내를 넣는 것을 권한다 |
| 7 | 중간 | 탐험이 진행 중일 때 화면을 다시 열면 "탐험에 보낼 슬라임을 골라 주세요."가 보인다 | 진행 중이면 "○○ 탐험 중이에요" 같은 안내가 맞다 |
| 8 | 낮음 | 용어가 섞여 있다: 튜토리얼은 "같은 **레벨**", 도감 효과 창은 "같은 **등급**" | 하나로 통일한다(화면 표기는 Lv.이므로 "레벨" 권장) |
| 9 | 낮음 | 말투가 섞여 있다: 상점 품목 설명 "~바뀝니다/~튕겨 냅니다", 도감 효과 토스트 "추가됩니다" ↔ 나머지 "~해요" | 해요체로 통일한다 |
| 10 | 낮음 | 옵션의 "진행도 초기화"(되돌릴 수 없는 동작)가 **초록색** 버튼이다 | 계정 삭제와 같은 경고색이나 회색이 의미에 맞다 |

| 12 | 낮음 | 광고 첫 시청에도 "포인트 2배 시간이 **늘었어요**!"가 나온다 | 남은 시간이 없을 때는 "포인트 2배가 시작됐어요!" |

참고로, Play Mode 중 스크립트를 고쳐 재컴파일됐을 때 `AdRewardService.Update`에서 NRE가 반복됐다. 에디터가 실행 중에 재컴파일하면서 생긴 것이라 실제 빌드와는 무관하다. 재시작 후에는 재현되지 않았다.

## 7. 자동화 테스트

`Assets/02.Scripts/Editor/Tests/` (asmdef 없이 `Assembly-CSharp-Editor`). Test Runner → EditMode → Run All. 54개 전부 통과.

**GameRulesTests** (47개, 규칙이 바뀌면 기대값도 함께 고친다)
- 포인트 계산: 특별 3배 × 광고 2배, 반올림(AwayFromZero)
- 도감 보너스: 3종마다 10%, 15종에서 50%로 멈춤
- 특별 피버: 3%에서 실패마다 +0.5%p, 최대 10%
- 뽑기 확률표: 최고 Lv.1~20 모두 합 1, 높은 등급일수록 낮음, 최고 등급 위 없음
- 뽑기 결과·특별·튜토리얼 뽑기의 등급 범위 (표본 2000회)
- 희귀도 = 최고 등급과의 거리(0–1 금, 2–3 보라, 4–6 파랑, 그 밖 초록)
- 조사 을/를, 큰 수 표기(K/M/B/T/aa, 지수 표기 없음)
- 포인트 획득량 업그레이드 구간(1/50/100/200 → 1/50/75/150%)과 비용 곡선, 업그레이드 표 전 항목 검증

**ContentAssetTests** (7개, 이번에 사람이 찾은 결함의 재발 방지)
- 튜토리얼·UiMessages 문구의 모든 글자가 두 글꼴(정적 아틀라스)에 있다
- 씬 라벨의 글자가 그 라벨 글꼴에 있다
- 코드에서 조립하는 화면 문자열에 `·`가 없다
- 문구에 줄바꿈 앞뒤 공백과 두 칸 공백이 없다
- 모든 대화 ID에 대사·화자가 있고, 뽑기 대화는 2줄 이상이다
- 소리 카탈로그의 효과음·테마별 BGM·장식장 BGM이 모두 채워져 있다
- 씬의 모든 버튼이 클릭음을 갖거나, 코드에서 소리를 내는 예외 목록에 있다

수정 전 버전(HEAD)에 이 검사를 대 보면 코드 문자열의 `·` 5건과 줄바꿈 공백 1건이 걸린다.

**아직 자동화하지 않은 것**
- 대사가 2줄을 넘는지: 대화창 폭에 맞춰 TMP로 재야 해서 Play Mode 테스트가 필요하다. 이번에는 `QaDriver`와 같은 방식으로 수동으로 쟀다.
- 튜토리얼 전체 시나리오: `QaDriver`로 이미 손으로 돌렸다. PlayMode 테스트로 옮기면 반복할 수 있다. 다만 LoginScene부터 시작해야 하고 PlayerPrefs를 지우므로, 테스트 전용 계정 키를 분리하는 작업이 먼저 필요하다.

## 8. 사용자 확인 필요

1. **화면**: 바뀐 대사가 의도한 말투인지. 특히 합친 대사(상점, 광고 보너스)와 줄인 대사(뽑기, 장식장 마무리).
2. **소리**: 업그레이드 실패 때 이제 부족 안내음만 난다. 탐험·동의 화면 버튼에 클릭음이 생겼다.
3. **기기**: TMP 한글 줄바꿈 규칙을 켜면 모든 화면의 줄바꿈 위치가 바뀐다. 이번에 캡처한 화면은 모두 나아졌지만, 고정 폭이 좁은 라벨(하단 버튼 등)은 기기에서 한 번 훑어보는 것이 좋다.
4. **세이브**: 테스트하면서 에디터 로컬 세이브를 지우고 새로 만들었다(사전 동의). 현재 에디터 세이브는 엔딩까지 본 상태이다.
