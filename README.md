# Monster Kindergarten

슬라임을 생성하고 같은 등급끼리 합성해 성장시키는 Unity 6 기반 Android
방치형 클리커 게임입니다. 클릭과 자동 생산으로 포인트를 모아 슬라임의
생산량과 공용 스폰 시스템을 업그레이드합니다.

## 게임

- 최고 해금 등급과 업그레이드 상태에 따라 1–6등급 슬라임이 일정 시간마다 자연
  생성됩니다.
- 같은 등급 두 마리를 드래그해 합치면 다음 등급으로 성장하며, 최대 20등급까지
  있습니다.
- 모든 등급의 슬라임이 한 필드에서 함께 지냅니다. 최고 등급 9부터 왼쪽 서랍의
  상점이 열리고, 하늘과 우주 배경을 구매해 가지고 있는 배경 중 하나를 골라 적용할
  수 있습니다.
- 최고 등급 3부터 장식장이 열립니다. 메인 필드의 슬라임을 전시하거나 다시
  꺼낼 수 있고, 넣은 일반 슬라임은 도감에 영구 등록됩니다. 전시 중인 슬라임은
  포인트를 생산하지 않고 수용량도 차지하지 않습니다. 장식장 슬라임은 서로 부딪히며
  돌아다니고, 상점에서 산 범퍼와 대포를 배치 모드로 놓아 놀이터를 꾸밀 수 있습니다.
- 슬라임 터치와 자동 생산으로 포인트를 얻어, 모든 슬라임의 포인트 획득량과 스폰 간격·최대
  수용량·상위 슬라임 등장 확률을 강화합니다. 포인트는 정수 단위입니다.
- 일반 도감을 3종 채울 때마다 모든 포인트 획득량이 10%씩 늘어납니다(최대 +50%).
- 최고 등급 7부터 필드에 뽑기권이 떨어집니다. 주운 뽑기권으로 1등급부터 최고 해금
  등급까지의 슬라임을 뽑을 수 있고(낮은 등급일수록 잘 나옵니다), 자동 스폰을 끄고
  켤 수 있습니다. 뽑기 버튼은 캡슐 뽑기 기계 화면을 열고, 1회·5회 버튼을 누르면 티켓이
  기계에 들어가 캡슐이 나옵니다. 캡슐을 눌러 열면 빛 색이 뽑힌 등급대를 알려 주고 슬라임이
  필드로 날아갑니다. 5회는 캡슐 다섯 개를 하나씩 열어 한꺼번에 보냅니다.
- 뽑기에서는 낮은 확률로 무지개 캡슐과 함께 무지개 외형의 특별한 슬라임이 나옵니다. 같은 등급의 일반
  슬라임보다 포인트를 3배 벌고, 장식장에 넣으면 도감 칸이 특별한 모습으로 바뀝니다.
- 일반 도감 10종을 등록하면 자동 합성 버튼이 열립니다. 누를 때마다 필드 전체에서
  낮은 등급부터 일반 슬라임을 합성하고, 두 마리가 서로에게 모여 합쳐지는 연출이
  나옵니다. 한 번에 합성하는 쌍은 전용 업그레이드로 1쌍에서 10쌍까지 늘어납니다.
  버튼 테두리를 따라 차오르는 게이지로 다시 누를 수 있는 시점을 확인합니다.
- 도감 12종부터 떨어진 뽑기권을 버튼 하나로 한 번에 회수하고, 15종부터는 접속하지
  않은 시간에 비례해 뽑기권을 받습니다. 도감에 등록한 20종을 장식장에 실제로 모두
  모은 뒤 장식장에 입장하면 졸업 연출이 나오고, 이후에는 도감의 졸업식 버튼으로
  다시 볼 수 있습니다. 최초 졸업식 통계는 그 순간에 고정되며, 이후 계속 쌓이는
  기록은 옵션의 `현재 게임 기록`에서 확인합니다. 졸업 기록이 없는 예전 계정은 다시보기에서 지금 기록으로
  채워 보여 줍니다. 졸업식은 단계별 안내가 나타날 때
  화면을 터치해 진행합니다. 순서는 슬라임 입장, 게임 기록, 축전과 감사 인사, 특별
  슬라임 예고이고 예고 화면에서 터치하면 끝납니다. 첫 졸업사진은 다음 터치까지
  유지되고, 다시보기의 졸업사진은 현재 장식장의 특별 슬라임 상태를 반영합니다.
  축하 별·물음표·꽃잎은 씬에 미리 배치된 UI를 재사용합니다.
- 접속하지 않은 시간만큼 오프라인 자동 생산 보상을 받습니다(자동 생산량의 15%).
- 하단 메뉴의 `광고 보너스`에서 보상형 광고를 선택해서 볼 수 있습니다(AdMob). 광고를 끝까지 보면
  10분 동안 포인트 2배(남은 시간은 최대 30분, 하루 6회)나 뽑기권 1장(뽑기가 열린 뒤, 하루 3회)을
  받고, 접속하지 않은 시간의 오프라인 보상은 광고를 보고 포인트를 2배로 받을 수 있습니다. 하루는
  한국 시간 0시에 바뀝니다. 부스트 중에는 화면 가장자리에 불꽃이 타오릅니다. 광고를 보지 않아도
  게임을 모두 즐길 수 있습니다.
- 처음 시작할 때 이용약관, 개인정보 수집 및 이용, 만 14세 이상 확인에 모두 동의해야 로그인할 수
  있습니다. 약관과 방침은 게임 안 팝업으로 읽고, 옵션에서 다시 볼 수 있습니다. 동의 전에는
  분석 수집과 광고 SDK를 쓰지 않습니다.
- 신규 플레이어와 새로 열리는 기능마다 튜토리얼이 안내합니다.

오프라인 보상은 오프라인 플레이를 의미하지 않습니다. Android에서 게임을
시작하려면 Google Play Games 및 Firebase 로그인이 필요합니다.

수치와 규칙을 포함한 확정 기획은
[게임 기획 및 Phase 구현 스펙](Documentation/MonsterKindergarten_GAME_DESIGN_IMPLEMENTATION_SPEC.md)에
있습니다.

## 개발 환경

- Unity `6000.3.21f1`
- Android / Universal Render Pipeline 2D
- Unity Input System `1.20.0`
- Google Play Games Plugin for Unity
- Firebase Authentication / Firestore `13.7.0`
- Google Mobile Ads Unity plugin `11.5.0` (AdMob 보상형 광고)
- Firebase Analytics: Android 라이브러리를 JNI로 호출합니다(Unity용 Analytics 라이브러리는 쓰지 않습니다)
- UniTask / DOTween / Lean Pool
- TextMesh Pro / UIEffect

## 실행

1. Unity Hub에서 Unity `6000.3.21f1`과 Android Build Support를 설치합니다.
2. 저장소를 Unity 프로젝트로 엽니다.
3. `Assets/01.Scenes/LoginScene.unity`에서 Play Mode를 실행합니다.

Editor에서는 `LocalPlayer` 계정과 로컬 저장소를 사용합니다. Google Play Games
로그인, Firebase 저장·복구, 터치 입력, 서명과 기기 성능은 Android 빌드에서 별도로
검증해야 합니다.

## 빌드 프로필

| 용도 | 프로필 |
| --- | --- |
| Play Console 배포 | `Android_Release` |
| 개발 및 기기 확인 | `Android™` |

Android 애플리케이션 ID는 `com.skku_say.Monster_Kindergarten`입니다. Release는
Development Build가 꺼진 AAB, 개발 프로필은 켜진 APK이며 둘 다 `LoginScene` 다음에
`GameScene`을 포함합니다. 개발 프로필도 릴리스와 같은 커스텀 키스토어로 서명합니다.
Google Play Games 로그인이 디버그 키스토어 빌드를 거부하기 때문입니다.

앱 버전과 Version Code는 프로필의 Player Settings 오버라이드에 있습니다. 프로젝트
전역 버전이 아니라 이 값이 실제 빌드에 쓰입니다. 현재 값은 [CLAUDE.md](CLAUDE.md)에
적어 둡니다.

산출물은 `Builds/Release/<버전>/`에 두며 Git에서 제외됩니다. 각 빌드의 구성과
검증 결과는 그 폴더의 `build-info.txt`에 남깁니다.

## 저장 구조

- 재화, 슬라임 상태, 업그레이드를 독립된 도메인과 저장소로 관리합니다.
- Android에서는 PlayerPrefs에 즉시 저장하고 Firebase에 지연 반영하는
  `HybridRepository<T>`를 사용합니다.
- 활성 슬라임은 개체별 `InstanceId`, 등급, 특별 여부와 위치를 저장하며 화면
  좌표는 저장하지 않습니다. 도감은 등록 상태와 등급별 누적 통계를 함께 남깁니다.
- 도메인마다 `SchemaVersion`을 기록하고, 현재 앱이 지원하는 것보다 높은 저장
  데이터는 구버전이 덮어쓰지 못하도록 로드를 중단합니다.
- 읽기는 "읽음 / 없음 / **실패**"를 구분합니다. 읽기 실패를 기본값으로 바꾸면 그
  세션이 신규 계정으로 시작하고 첫 저장이 읽지 못한 원본을 덮어쓰기 때문입니다.
- 해석할 수 없는 저장을 만나면 게임에 들어가지 않고 안내와 함께 로그인 화면으로
  돌아갑니다. 손상된 경우에는 그 화면에서 진행도를 초기화해 복구할 수 있습니다.
- 메인 튜토리얼 중에는 진행 저장을 잠그고, 완료 시 세 도메인을 함께 저장합니다.

저장 규칙의 세부는 [CLAUDE.md](CLAUDE.md)에 있습니다.

## 옵션과 진행도 관리

- 배경음·효과음 음량과 프레임(60/120)은 기기별로 저장하며 재실행 시 복원합니다.
- 진행도 초기화는 확인창을 거쳐 현재 계정의 재화·슬라임·업그레이드와 이 기기의
  튜토리얼 기록을 삭제하고 로그인 화면으로 돌아갑니다. 인증 계정과 음량·프레임 설정은
  남습니다.
- 계정 삭제는 같은 정리를 마친 뒤 Firebase 인증 계정을 삭제합니다. Google 계정과
  Play 게임 프로필은 삭제하지 않습니다.
- 초기화나 계정 삭제가 중단되면 다음 로그인에서 게임 진입 전에 마무리합니다.
- 다른 기기의 로컬 저장까지 무효화하지는 않습니다. 그 기기로 접속하면 이전
  진행도가 클라우드에 다시 저장될 수 있습니다.

## 현재 상태

Phase 1·1.5 자연 스폰과 개체 저장, Phase 2 장식장, Phase 2-B 관찰 UX, Phase 3 일반
슬라임 도감, Phase 4 뽑기권, Phase 5 특별 슬라임, Phase 6 자동 합성, Phase 7 도감
마일스톤, Phase 8 UX·튜토리얼·밸런싱·QA를 모두 `main`에 병합했습니다.
`feature/phase-8-ux-qa`는 2026-10-02에 PR #26으로 병합했고, 장식장 놀이터와 상점,
특별 슬라임, 졸업식 개편과 놀이 기록, 업그레이드 곡선과 도감 포인트 보너스, 튜토리얼
정비와 대규모 구조 정리가 포함됩니다. Phase 9 보상형 광고(광고 보너스, 오프라인 2배, 약관 동의, 광고 지표)는 1~9단계까지
`main`에 들어갔고(10단계 뽑기 기계 입구는 선택), 개발 APK `0.1.17`(Android Version Code 19)에서
사용자가 광고, 동의, 분석 흐름을 기기로 확인했습니다. 릴리스 AAB `0.1.17`은 병합 매니페스트까지
확인했고 기기 확인은 남아 있습니다. 기기 검증 결과가 있는 것은 `0.1.13`까지의 내용과 `0.1.17`
개발 APK의 Phase 9 흐름이며, `0.1.14`~`0.1.16`에서 처음 들어간 기능(캡슐 뽑기 기계, 가로로 넓은
화면 대응, 로그인 연출, 터치 효과 등)은 기기 확인이 남아 있습니다.

검증은 세 층으로 쌓습니다. Unity Editor에서 Firestore 없이 닿는 경로를, 개발
APK에서 클라우드가 필요한 경로를, 릴리스 AAB에서 코드 스트리핑까지 걸린 실제
구성을 확인합니다. 앞 단계의 결과를 다음 빌드의 검증 완료로 확대하지 않으며,
실행 테스트는 사람이 직접 수행합니다.

빌드별 검증 항목과 결과는 `Builds/Release/<버전>/build-info.txt`에, 현재 무엇이
확인됐고 무엇이 남았는지는 [CLAUDE.md](CLAUDE.md)에 있습니다.

게임은 세로 전용입니다. 프로젝트 설정과 두 Android 빌드 프로필 모두 Portrait 외의
방향을 허용하지 않습니다.
